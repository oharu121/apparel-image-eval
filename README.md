# Apparel image eval

A small hobby evaluation of image models for one apparel task: given a garment line drawing
(or an existing garment photo) and a fabric swatch, generate a realistic product image of that
garment made from that fabric.

Main model: OpenAI `gpt-image-2.6-sunburst` through `POST /v1/images/edits`, which takes up to
16 input images in one call. `gpt-image-2.6-flare` is the cheap smoke-test model. Google's
Nano Banana models may be compared later.

## Ground truth for free

Every case starts from a real public-domain photo of a garment:

1. A flat, front-on fabric area is cropped from the garment → `inputs/fabric.jpg`
2. A black-on-white line drawing is made from the photo → `inputs/line_drawing.png`
3. The original photo is kept as `ground_truth/photo.jpg` and is never sent to the model

The model then has to rebuild the garment from the drawing and the swatch, and the result can
be compared with the real thing.

## Layout

```
data/
  SOURCES.csv          one row per file: source URL, licence, author, derived_from, synthetic
  manifest.json        generic rules, prompt templates, per-case inputs and scale notes
  cases/<id>/
    source/            downloaded originals + museum metadata JSON
    inputs/            sent to the model
    raw_crops/         crops before any colour correction
    ground_truth/      never sent to the model
    _crop_log.json     crop box and method for every derived file
scripts/
  fetch_met.py         search / download Met Open Access garments, checking public-domain status per object
  make_fixtures.py     source photo → swatch, line drawing, ground truth
  run.py               generation, with --dry-run, --max-cost and skip-if-exists
  autocheck.py         colour ΔE vs swatch and pattern repeat count, for patterned cases
  gallery.py           static HTML gallery with a blind scoring mode
results/
  <model>/<case>/<variant>_r<round>_s<n>.png
  log.csv              model, size, quality, latency, tokens and cost per call
  autocheck.csv
gallery/index.html
```

## Rules

- Inputs are CC0 or public domain only, with the licence verified per file and recorded in
  `data/SOURCES.csv`. An input generated by a model is marked `synthetic`.
- The Met's search endpoint returns objects whose own record says `isPublicDomain: false` even
  when the search is filtered to public domain, so `fetch_met.py` re-checks every object.
- Round 1 uses the prompt template in `manifest.json` unchanged for every case. Prompt fixes go
  in round 2 and are logged with `--round 2`.
- Three samples per case × model × variant. The API has no seed parameter, so samples are
  independent draws, not reproducible runs.
- The API key is read from `OPENAI_API_KEY` and never written to the repo.

## Running

```bash
uv sync
uv run scripts/fetch_met.py search plaid
uv run scripts/fetch_met.py get C03 <object id>
# set case.fixture boxes in manifest.json, then check them:
uv run scripts/make_fixtures.py C03 --preview
uv run scripts/make_fixtures.py C03
# set case.status to "ready"
uv run scripts/run.py --dry-run
OPENAI_API_KEY=... uv run scripts/run.py --cases C03 --samples 1 --max-cost 0.5
uv run scripts/autocheck.py
uv run scripts/gallery.py && open gallery/index.html
```

## Cost

Standard-tier token prices, identical for both 2.6 models (checked 2026-11-24):
$5 / 1M text input, $8 / 1M image input, $30 / 1M image output. `run.py` records the cost of
each call from the response's `usage` field; the `--max-cost` guard uses a conservative
pre-call estimate.

## Scoring

Each output is scored 1–5 on silhouette vs drawing, fabric/pattern fidelity, pattern scale,
colour, material texture, construction details, and whether it is usable for a planning
decision.
